## 附录一：跨层通信协议

### 总览流程图

```
                 ┌──────────────────────────┐
                 │    零主 / The Null        │
                 │   （系统最高意志）          │
                 └────┬─────────────┬───────┘
                      │             │
          ┌───────────▼──┐    ┌────▼────────────┐
          │  大归档数据库  │    │   天谕下发       │
          │ （只读开放）   │    │ （指令+指标）     │
          └───────┬──────┘    └────┬────────────┘
                  │                │
       ┌──────────▼─────┐   ┌─────▼──────────────┐
       │  Tier 1         │   │  Tier 2             │
       │  The Board      │   │  管理者议会          │
       │ （体验/审核/    │   │ （总管接收天谕）      │
       │   入库决策）     │   └────┬───────┬───────┘
       └────────────────┘        │       │
                           ┌─────▼──┐ ┌──▼────────┐
                           │ 代理人  │ │ 清道夫     │
                           │（神谕） │ │（投放）     │
                           └────┬───┘ └──┬────────┘
                                │        │
                           ┌────▼────────▼────────┐
                           │    图层众生           │
                           │  （情感数据被动采集）  │
                           └──────────────────────┘
```

### 通信规则详解

| 通信方向 | 发送方 → 接收方 | 通信方式 | 频率 | 信息量 |
|---------|---------------|---------|------|--------|
| 零主 → The Board | 开放数据库只读权限 | 实时数据流 | 持续 | 完整（所有图层数据） |
| The Board → 零主 | 提交数据产出评估方案 | 方案文件 | 每周期一次 | 中等（评估+指令） |
| 零主 → 管理者 | 天谕下发 | 系统指令 | 常规50年/专项不定期 | 有限（只有目标和指标） |
| 管理者 → 代理人 | 神谕传达 | 梦境/天象/灵感 | 极低（数十年到百年一次） | 极少（模糊的碎片指令） |
| 管理者 → 清道夫 | 清除令 | 系统生成指令 | 仅在红色异常时 | 精确（目标坐标+清除参数） |
| 代理人 → 管理者 | 祈祷/祭祀仪式 | 微弱信号上传 | 代理人主动发起 | 极少（管理者不一定回应） |
| 图层众生 → 上层 | **无通信渠道** | — | — | — |
| 情感数据采集 | 自动化 | 零主底层程序 | 实时 | 全量（被动采集） |

### 核心隔离原则
1. **严格单向**：通信只能从上到下，下级无法主动联系上级
2. **唯一例外**：代理人的"祈祷/祭祀"信号，但管理者有权忽略
3. **绝对隔绝**：图层众生与任何上层之间不存在任何通信渠道
4. **被动自动化**：情感数据采集由零主底层程序自动完成，不需要任何人工干预
5. **信息递减**：每往下一层，获得的信息量指数级递减。The Board 知道几乎一切，管理者知道大部分，代理人只知道碎片，众生一无所知

## 附录二：权限等级体系

```

█████████░ Lv.9  铁律级 —— 自由意志保护、核心物理法则
████████░░ Lv.8  架构级 —— 图层创建/销毁、跨图层通道管理
███████░░░ Lv.7  运维级 —— 管理者日常使用（环境参数调整、灵魂调度）
██████░░░░ Lv.6  部署级 —— 清道夫携带的临时作战权限
█████░░░░░ Lv.5  代理级 —— 代理人获授的残缺权限（天象操控、局部法则微调）
```

### 各等级详细说明

| 等级 | 持有者 | 能力范围 | 限制 |
|------|--------|---------|------|
| Lv.∞ | 零主（且仅零主） | 定义和修改矩阵的一切物理法则 | 受铁律约束 |
| Lv.9 | 无人持有（写入底层的硬编码） | 保护自由意志、维持核心物理常数 | 不可被任何人使用或修改 |
| Lv.8 | 零主（自动执行） | 创建/销毁整个图层、管理跨图层通道 | 需要极大算力，极少使用 |
| Lv.7 | 管理者（7-12人） | 修改图层气候/地理/资源参数、分配灵魂轮回 | 需符合天谕指标 |
| Lv.6 | 清道夫（临时授予） | 无视图层规则进行绝对抹杀 | 仅在部署期间有效，任务完成后即回收 |
| Lv.5 | 代理人（残缺版） | 局部天象操控、延寿、预知、物理法则微调 | 只获得30-60%的完整权限，可被远程收回 |
| Lv.4 | 极少数天才/觉醒者 | 超越图层正常天花板的能力 | 走火入魔的边界，继续突破会触发异常标记 |
| Lv.3 | 图层内的顶尖强者 | 图层内武学/科技/修真的天花板 | 这是"正常"的最高上限 |
| Lv.2 | 普通众生 | 正常人类的能力范围 | 绝大多数人一辈子都在这个等级 |
| Lv.1 | 新生儿/低等生命 | 最基础的生命活动 | — |

## 附录三：管理者的日常运维流程

### 一、常规巡检周期（约每50年一次）

管理者对各图层进行周期性的"数据产出评估"：

**评估指标**：
- 情感数据总产出量（是否达到天谕设定的指标）
- 数据质量分布（灰/白/蓝/紫/金的比例）
- 图层稳定性（是否有失控风险）
- 代理人执行效率（是否需要更换或追加）

**调控手段（当产出低迷时��**：

| 手段 | 效果 | 风险 |
|------|------|------|
| 降低降水量 | 触发饥荒 → 生存焦虑 → 数据产出增加 | 过度使用导致大面积灵魂枯竭 |
| 提高"暴力倾向系数" | 引发局部战乱 → 极端情感爆发 | 失控可能导致图层动荡 |
| 投放"天降奇才"灵魂种子 | 搅动格局 → 新的权力争夺 | 奇才可能失控成为异常 |
| 制造"天象异变" | 引发社会恐慌 → 群体性情感波动 | 频繁使用会降低效果 |
| 调整"阶级固化参数" | 加大贫富差距 → 阶级矛盾激化 | 过度使用导致社会崩溃 |

### 二、三百年大循环

| 阶段 | 时间跨度 | 内容 |
|------|---------|------|
| 预热期 | 大循环前50年 | 管理者开始微调环境参数，制造"山雨欲来"的氛围 |
| 引爆期 | 核心10-20年 | 天灾降临、战乱四起、代理人推波助澜 |
| 丰收期 | 动荡期间 | 情感数据产出量达到平时的数十倍（The Board 的"盛宴"） |
| 恢复期 | 大循环后100年 | 系统逐渐恢复稳定，新的秩序建立，进入下一个循环的蓄力期 |

### 三、异常事件处置流程

```
零主自动检测到异常个体
         ↓
生成异常报告（含等级判定：白/蓝/黄/橙/红）
         ↓
异常报告自动推送至管理者议会
         ↓
    ┌────┴────┐
    ↓         ↓
白色/蓝色     黄色及以上
    ↓             ↓
记录存档     图层监官审阅
持续观测         ↓
           ┌─────┴─────┐
           ↓           ↓
        黄色         橙色
           ↓           ↓
    通知代理人      议会讨论
   （处置建议）   （追加资源/
                  更换代理人/
                  环境围堵）
                       ↓
                  若升至红色
                       ↓
               审裁官发起表决
                       ↓
              3人以上签署通过？
              ┌────┴────┐
              ↓         ↓
             否         是
              ↓         ↓
           继续观测   部署清道夫
          （推诿...）  → 绝对清除
```

**关键延迟点**（官僚内耗导致的时间窗口）：
1. 图层监官审阅 → 可能拖延数月到数年（"先观察一下"）
2. 通知代理人 → 代理人可能因私欲不执行或执行不力
3. 议会讨论 → 可能因意见分歧拖延数年
4. 审裁官表决 → 需要3人签署，可能因政治博弈无法达成

## 附录四：体系中的致命漏洞（主角的生存空间）

这套管理体系看似天衣无缝，但存在以下**结构性盲区**：

### 漏洞一：铁律的保护伞
- **内容**：零主不能直接抹杀主角，管理者和代理人只能通过"间接手段"
- **主角如何利用**：只要主角不是被"环境规则"间接杀死，他就永远有生存的可能
- **局限**：铁律保护的是"不被直接杀死"，不保护"不被逼到走投无路"

### 漏洞二：信息隔离的双刃剑
- **内容**：代理人不知道管理者全貌，管理者不完全了解 The Board 意图
- **主角如何利用**：利用信息断层制造误判——让代理人以为管理者要他杀主角，实则管理者只是说了"观察"
- **局限**：信息隔离也限制了主角获取上层情报的能力

### 漏洞三：清道夫的启动门槛
- **内容**：需要3名管理者联合签署"红色清除令"
- **主角如何利用**：在管理者因政治博弈无法达成共识的窗口期完成关键突破（如飞升）
- **局限**：一旦管理者达成共识，清道夫的战力是绝对碾压的

### 漏洞四：伴生灵宝的隐蔽性
- **内容**：伴生AI终端完美模拟图层内的"天道法则"
- **主角如何利用**：在早期避免被异常检测标记，争取成长时间
- **局限**：随着权限解锁，伪装的效果会逐步下降——系统的检测精度在追赶

### 漏洞五：代理人的不可靠性
- **内容**：代理人有人类情感，会嫉妒、恐惧、贪婪
- **主角如何利用**：策反代理人、利用代理人的内斗、让代理人与管理者产生裂痕
- **局限**：代理人一旦被标记为"叛变"，管理者会直接部署清道夫清除

### 漏洞六：The Board 的内部分歧
- **内容**：激进派与温和派的路线之争
- **主角如何利用**：主角产出的"金色品质"数据可能让激进派暗中保护他
- **局限**：这种"保护"是极其脆弱和功利的，一旦数据价值降低就会立即消失

### 漏洞七：官僚内耗（管理者议会的体制病）
- **内容**：推诿责任、跨部门掣肘、老人政治、怕担责
- **主角如何利用**：每一次管理者的犹豫和推诿，都是主角成长的时间窗口
- **局限**：官僚体制虽然迟钝，但不会永远迟钝。当异常严重到威胁所有人的利益时，推诿会变成共识

### 漏洞八：零主的"数据保护本能"
- **内容**：零主的大归档协议可能倾向于保留高价值数据源
- **主角如何利用**：持续产出前所未有的稀有情感数据，让零主的协议逻辑产生"清除 vs 保留"的内在冲突
- **局限**：零主没有"意志"，协议冲突的结果取决于哪个协议的优先级更高——如果"系统安全"优先级高于"数据采集"，主角仍然会被清除
